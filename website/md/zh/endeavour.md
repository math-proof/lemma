# 研究路线图

[lemma.cn](../../index.php) 的长期方向是**数学机械化**（Mathematics Mechanization），与中国科学院 [数学机械化重点实验室](http://www.mmrc.iss.ac.cn/) 的研究主题相近。就公开可访问的形式化资源而言，完全自动化的数学证明仍是开放难题；本项目的目标是逐步构建**公理化、可机器检验、源码开放**的定理库与证明环境。

当前库中已收录约 5000 条经 Lean 4 检查的定理（见主页计数），覆盖多个数学分支。后续工作拟分阶段推进：

1. **规则驱动的交互式证明系统（已基本完成）**  
   基于依赖类型论与定理库的半机械化推理环境已可用，但仍需持续修复缺陷、扩展引理并完善工具链。

2. **大规模定理知识库（进行中）**  
   目标是在本项目的同一形式体系（`Tensor` 演算及关联数学分支）内积累 **100 万**量级可复用的形式化定理。Lean 生态中的 [Mathlib](https://leanprover-community.github.io/mathlib4_docs/) 已率先达到 **10 万**量级，表明该规模在依赖类型论下可行；本项目则瞄准与人类历史上已证数学定理总量的粗量级（约 **100 万**）相当的形式化覆盖。属长期工程，需社区协作；时间尺度取决于贡献规模。

3. **LLM 编程智能体辅助证明（进行中）**  
   在阶段 2 的定理库与 Lean 源码之上，实践当前 **coding agent** 范式：大语言模型在**人机协同**循环中读取仓库上下文、调用工具（引理检索、`lake build`、LSP 诊断、callee/caller 依赖图等），起草或补全证明脚本；人类审查与修正，**Lean 4 核**仍作最终裁判。这与通用软件工程中最先进的智能体流程同构——**仓库感知**（RAG / 全库索引）、**工具调用**（终端、构建、语言服务器）、**编辑—编译—修复**迭代（如 [Cursor Agent](https://cursor.com/)、GitHub Copilot、Claude Code 等）——智能体加速引理检索、tactic 选择与证明草稿编写，**不取代**形式化核验。形式化证明方向的对标工作包括 [LeanDojo](https://leandojo.org/)（Lean 检索增强定理证明）、[ProofNet](https://proofnet.github.io/)（本科数学 Lean 自动形式化基准）及 [GPT-f](https://arxiv.org/abs/2109.04561)（大模型辅助形式化证明的早期代表）；本项目侧重 coding agent 与 **lemma.cn** 定理库及 Web 检索接口的集成，而非端到端全自动证明竞赛。

4. **半监督 / 无监督定理发现（研究性）**  
   探索从已有定理库中自动提出候选命题，并在现有规则与引理下尝试完成证明，以扩展库的内容（需严格区分「猜想」与「已证定理」）。

5. **抽象数学语言与程序语言的统一（远期目标）**  
   在前述阶段之上，使计算机系统更系统地表述、组合与验证抽象数学结构，作为数学研究与算法形式化验证的基础设施。

本路线图描述的是研究方向与阶段性目标，不构成对实现时间表或技术路线的承诺；各阶段均可独立使用当前已公开的定理库与 Lean 4 证明工件。
