# Lemma linter (`mjs/lean/lint/`)

The mechanically checkable style rules of `AGENTS.md`, reported as **warnings** (never errors) by the compiler:

- `render2vue.mjs` `echo2vueFromSource` → `code.warning` (only when non-empty), so they show up in the
  `request/echo` JSON and in `node mjs/run.mjs <file>` (stderr, `warning:LINE:COL: [rule-id] … (AGENTS.md: "…")`).
- `node mjs/run.mjs --fix <file>` applies the fixable rules' fixes in place (currently `header-spacing` —
  the `module` header's leading blank run and the two-blank trailer of a module file — plus
  `paren-redundant-ascription` and `paren-redundant-arith`)
  and stops before compiling; the warning list is re-run until stable.
- They never change the lemma status, `run.mjs`'s exit code, or the `axiom.lemma` row (`warning` is not a saved column).

Two passes:

- **Text scan** (most rules): the source with comments / strings blanked (`scan.mjs`), a bracket matcher, and a small
  binder-signature parser. Reports `line` / `col`.
- **AST pass** (`astRules.mjs`): the file is parsed with lean.js (`compile`, the same parser as the renderer; a separate
  tree, since `echo` mutates it). `compile` stamps every node with a 1-based source `line` (no columns), so
  `w.line = node.line`; these warnings also **quote the offending statement**: `w.stmt` is the node's own reprint
  (`String(node)`), trimmed to its first line(s) / ~120 chars with `…`. A text search (`locate`) is only the fallback
  for a synthetic quote (`quoteAs`) or `paren-redundant-arith`, whose pretty-printed reprint may differ from the source.
  `run.mjs` prints

  ```
  warning:23: [have-inline-once] `h₁` is used only once, by the next `exact`: … (AGENTS.md: "…")
      > have h₁ : n = n := by
      >   simp
  ```

  If the parse throws, the AST rules are skipped silently and their text-scan versions run instead (`AST_RULES` /
  `ctx.astCovered`), so a rule never reports twice. Layout rules (bullets, indentation, line breaks around operators)
  stay text-based: the reprint normalizes layout.

| `given-unused` | explicit proposition binders under `-- given` (same prop/expr idea as `propKind` / `isPropositionType`; not `{…}` / `[…]` above `-- given`, not expression binders). A name still mentioned in a later given or the imply is kept. | `inst-unused` | named instance binders `[h : T]` (and `[_ : T]`) above `-- given` / `-- imply`. | `imply-semicolon` | top-level (bracket-depth 0) statement-separator `;` in `-- imply` only, e.g. a `let` / `have` terminated with `;` before the conclusion, or several imply statements joined by `;`. Suggests omitting `;` and using a newline (if the next statement is already on the next line, keep it there and drop the `;`; if both are on the same line, put the following statement on a new line). Comments / strings are blanked by `prepare()`. A `;` inside brackets such as `(by foo; bar)` is skipped. An interior tactic `;` after a depth-0 `by` (same-line continuation, or a more-indented `by` body line) is also skipped; a trailing `;` that ends that `have` / `let` is still flagged. `-- given` and `-- proof` are out of scope. | `imply-unused` | named `let` / `have` binders in `-- imply` only (`let h : T :=`, `have h :=`, and the `_` forms `let _ : T :=` / `have _ :=`). Unused means the name does not appear as a *use* in the rest of `-- imply` (including a later imply binder's type) or in the `-- proof` (same identifier scan as `given-unused` / `inst-unused`, starting after the binder's RHS). Mentions in the proof **do** count: if the proof refers to `h`, dropping the name would break it (unlike `inst-unused`, where an anonymous `[T]` is still found by typeclass inference). Suggests dropping the name: `let h : T :=` → `let : T :=`, `have h :=` → `have :=` (both typeless anonymous forms appear in the corpus). Already-anonymous `let : T :=` / `have : T :=` / `let :=` / `have :=` are left alone. Pattern binders (`let ⟨a, b⟩ :=`), `let rec` / `let mut`, and function lets (`let f x :=`, `let f (x : T) :=`) are skipped. Only statement-level `-- imply` binders (not `-- given`, not `-- proof`, not a `let` / `have` interior to a depth-0 `by` block). Prefer dropping the name over `binder-underscore-name` on the same line. Not an AGENTS.md rule (no quote) | `signatureRules.mjs` |
| `tactic-haveI`, `tactic-letI` | `Lean_have` / `Lean_let` with the parser flag `inst` (parsed from `haveI` / `letI`), outside declaration signatures | `proofRules.mjs` |
| `calc-after-assign` | `have` / `let` (incl. `haveI` / `letI`) whose `:=` value is a `LeanArgsNewLineSeparated` holding only a `LeanCalc`, i.e. `:=⏎ calc`; the same-line form `:= calc` has the `LeanCalc` itself as the value. Not an AGENTS.md rule (no quote) | — (AST only) |
| `fin-index-val` | `LeanGetElem` whose index atom / slice bound is a `.val` projection or `↑` (`y[i.val]`, `y[↑i]`, `y[:i.val]`, `y[p.1.val]`); prefer bare `y[i]` (not `↑i`). Skips deeper `.val`/`↑` in arithmetic (`y[i.val + 1]`). Not an AGENTS.md rule | — (AST only) |
| `fin-getelem-app` | per `Lean_lemma` / `Lean_theorem`: collects signature binders whose type is a `Fin`-headed arrow (`(f : Fin d → α)`, `{p q : Fin d → Prop}` — predicates included), then flags each `LeanArgsSpaceSeparated` two-arg application `f t` of those names in the statement and proof, suggesting `f[t]` getElem indexing. When `Instance.Data.Fin.Fun` is **not** imported yet, the message additionally asks for that import (its `GetElem (Fin n → α) ℕ α` instance coerces the Fin index to ℕ, `t < d` discharged by `get_elem_tactic`); with the import present the suggestion stands alone. Binder name lists (`{p q : …}`, a colon's lhs) and lambda binder lists (`fun f t => …`, the `⇒`/`λ` lhs) are not applications and are skipped; multi-argument applications (`f t u`) are out of scope. Idempotent: `f[t]` itself is a `LeanGet`, never flagged. Warn-only, no `--fix` | — (AST only) |
| `paren-getelem` | `LeanParenthesis` whose `arg` is a `LeanGetElem` (`(x[t])`, `(x[t:])`, `(«\sf{s}»[t])`); suggests dropping the parens. Skips `(f x)[t]` (arg is application), `(x[t] + 1)` (arg is not GetElem), and the body delimiters of `ℙ` / `𝔼` / `𝕍𝕒𝕣` / `ℂ𝕠𝕧` (`𝔼[x[k]: π](x[k])` is the notation's own parentheses). Not an AGENTS.md rule | — (AST only) |
| `paren-redundant-type` | explicit binder `(h : (T))` whose type is a `LeanParenthesis` that is not an ascription `(e : τ)`, tuple, or `·` section; suggests dropping the outer wrap (`(hMs : (sup[…] e < ∞))` → `(hMs : sup[…] e < ∞)`). Not an AGENTS.md rule | — (AST only) |
| `paren-redundant-sum-sub` | `LeanParenthesis` whose `arg` is `Lean_sum` / `Lean_prod` and whose parent is `LeanSub` with this node as `rhs` (`a - (∑ …)` / `a - (∏ …)`); suggests dropping the parens. Does **not** warn for `(∑ …) + d k` (LHS of `+`, meaning-changing). Not an AGENTS.md rule | — (AST only) |
| `paren-redundant-pow` | `LeanParenthesis` whose `arg` is `LeanPow` with an already-parenthesized base (`((a - b) ^ 2)`); suggests dropping the outer parens. Skips app-arg / the parenthesized `^` itself applied to an argument (`((γ * ℓ) ^ (id : ℕ → ℕ)) k`; application binds tighter than `^`) / property / GetElem / nested-pow-LHS / ascription / left operand of `@` (`((_ ^ _)) @ _`; `^` binds tighter than `@`). Not an AGENTS.md rule | — (AST only) |
| `paren-redundant-arith` | `LeanParenthesis` under binary `LeanArithmetic` whose pair can be removed without changing the parse: re-parse `lhs op rhs` with and without the pair and compare the trees (paren-insensitive), on either side and for nested groups (`(((a)) * b)` → `(a * b)` over repeated `--fix` passes). Covers repo term macros (`((∇[x] F x) - g)` → `(∇[x] F x - g)`, `∂[x] …`) and applications (`((f x) + y)` → `(f x + y)`). Skips ascriptions `(e : τ)`, tuples, `·` sections, repo `⬝ᵥ` (`Dot.dot` via `pathDotV` / `infixl:72 (priority := 2000)`, Mathlib `dotProduct` fallback) as a **parent** (a trailing `fun` in its RHS swallows `=`, `|`, `:=`, and `γ ^ range (k + 1) ⬝ᵥ v` takes `range (k + 1)` as the `Dot.dot` argument), while a `⬝ᵥ` **operand** is dropped only when the operator binds no tighter (`(∂[x] F x - ((F x).softmax ⬝ᵥ ∂[x] F x))` → `(∂[x] F x - (F x).softmax ⬝ᵥ ∂[x] F x)`), a child whose right spine ends at `fun` (the lambda would swallow `=`, `|`, `:=`), parens around a `•` (`SMul`) numerator of `/` (dropping them previously broke `field_simp` in `is_weight_eq_score`), and parens whose operand contains a big operator (`∑` / `∑'` / `∏`; the binder comma would swallow following `+` / `-`, e.g. `|(∑ … - ∑ …) + …|`, even when the AST reprint looks like `((∑ …) - (∑ …))`), and `∇` / `∂` / `∫` / `𝔼` macro bodies (`term:67`) followed by a tighter operator (`(∇[θ] …) * x`, `… • (∇[θ] …)`); `if` / `fun` / `let` / `match` / `by` / `calc` / `do` operands are kept. Also skipped when the reprint cannot be located in the source (no line number). Fixable: `--fix` drops the operand's outermost pair, keeping the operator parens. Not an AGENTS.md rule | — (AST only) |
| `paren-redundant-ascription` | `LeanParenthesis` around an ascription `(e : T)` whose value `e` is itself a `LeanParenthesis`, i.e. `((e) : T)` / `(((e)) : T)`; suggests `(e : T)`. Conservative: the parens are dropped only when re-parsing `(e : T)` reproduces the same ascription (lhs/rhs reprints equal), and never for a value whose parens are load-bearing — `fun` (the colon would rebind into the lambda), `if` (`LeanIte`), `by`, tuples, structure literals, `⟨…⟩`, nested ascriptions (`(h : P) : Q`), `match`, `let`, `do`, `calc`. Fixable: `--fix` drops the inner pair. Not an AGENTS.md rule | — (AST only) |
| `prefer-unicode-type` | `LeanParenthesis` / `LeanBrace` whose arg is `LeanColon` with bare ASCII type token `Nat`/`Int`/`Rat`/`Real`/`Complex`/`Hyperreal`; prefer Unicode `â`/`â¤`/`â`/`â`/`â`/`â*`. | `prefer-unicode-pow` | `LeanPow` whose exponent is the literal `2` / `3` / `4` (parentheses allowed) and whose base is one term; prefer the postfix `²` / `³` / `⁴` (`x ^ 2` → `x²`). Skips `x ^ (2 : ℕ)` and a base with a top-level space (`f x ^ 2`, `ι Y ^ 2`): postfix binds to the last atom, so `f x²` would mean `f (x²)`. Not an AGENTS.md rule | — (AST only) |
| `public-section` | `Lean_section` whose `kwargs.accessibility` starts with `public` — the parser leaves it undefined for a plain `section` (getter still defaults to `public`), so only the written modifier matches; `private section` / `noncomputable section` never do. `Theorem/` paths only. Warn-only, no `--fix` (deleting the section would silently make its declarations private in a module file) | — (AST only) |
| `range-binder` | a binder over a literal `Finset.range …` application: `LeanBigOperator` (`∑` / `∏` / `⋃` / `⋂` / `⨆` / `⨅`) and quantifiers (`∀` / `∃` / `∃!`; Mathlib's `∃!` notation accepts any `binder_predicate`). Suggests the `<` binder: `∑ i ∈ Finset.range n, f i` → `∑ i < n, f i` (big operators map `<` to `Finset.Iio n` via `processBigOpBinder`) and `∀ i ∈ Finset.range n, P i` → `∀ i < n, P i` (`∃` / `∃!` likewise). Only a literal range application matches: `Finset.range n \ {i}`, `Ico` / `Iic` / `Ioi`, `Set.range`, and `Finset.range` as a plain term are silent; `∑'` / `∫` are excluded (their notation has no `<` binder). A reprint containing `"` is skipped: lean.js does not lex string literals, so a mention inside `"…"` would otherwise reach the tree. The warning quotes the operator + binder (e.g. `∀ i ∈ Finset.range n`) and locates it as the n-th identical spelling in the comment/string-blanked source, so repeated binders in one file get their own lines. Warn-only, **no `--fix`**: both forms are only propositionally equal, never `rfl` — big operators via `Nat.Iio_eq_range`, quantifiers via `Finset.mem_range` (membership form vs implication form) — so a syntax-only rewrite can break proofs (e.g. `rw` no longer finds the `Finset.range` pattern; `Finset.sum_congr rfl h` rejects `∀ i < n` and needs `fun i hi => h i (by simpa using hi)`). Not an AGENTS.md rule | — (AST only) |
| `literal-left-comparison` | `LeanRelational` (`≤` / `<` / `≥` / `>`) whose **left** operand is a bare digit literal and whose **right** operand is a variable token (`2 ≤ n`): suggests the reversed, conventional form (`n ≥ 2`, `n > 2`, `n ≤ 2`, `n < 2`). Inspected **only in lemma/theorem signatures** (`given` hypotheses and the conclusion) — proof statements (`have`, `show`, `rw`, `simp`, `exact`, …) are never flagged. Skips `=` / `≠`, filtered relations (`≤ᵐ[μ]`), ascriptions (`(1 : ℝ) < n`), compound operands (`2 ≤ n + 1`, `2 ≤ Nat.succ n`), non-variable right tokens (`2 ≤ 3`, `2 ≤ N`), and `this` / `_`. Warn-only. Not an AGENTS.md rule | — (AST only) |
| `dot-notation` | `LeanArgsSpaceSeparated` whose head is a two-component dotted constant `N.f`. With two args, the sole explicit arg is the receiver (`Fin.ropeEven t` → `t.ropeEven`). With 3+ args, generalized field notation: the receiver is the **last** explicit arg, and it rewrites to `obj.f a1 … ak` (`Fin.castAdd d t` → `t.castAdd d`) when every explicit arg is a bare identifier, the last one's declared type *head* is `N` (`Fin d` → `Fin`), and no earlier arg shares that head (`Fin.h t u` is skipped because both `t` and `u` are `Fin` — the receiver slot would be ambiguous). A scope-tracked environment is kept in source order: declaration binders (incl. `{…}` above `-- given`), `∑` / `∏` / `∀` / `∃` binder lists, `fun` parameters, typed `let` / `have` (in scope only for later statements), and `Sum.inl` / `Sum.inr` patterns whose scrutinee `A ⊕ B` comes from the enclosing typed `let` (`A ⊕ B ≃ C` is parsed as `A ⊕ (B ≃ C)`, normalized back). Nearest binding wins (shadowing). Matching is spelling-strict (tested in `astRules.dotNotation.test.mjs`): matches the type head token against the namespace verbatim; skips notation aliases (`ℕ`/`Nat`, `ℝ`/`Real`) and coercion-rendered types (`EuclideanVec d`); requires an annotated binder (unannotated / `obtain` / `rcases`-introduced variables are skipped). The alias silence is the style filter, not a miss: `n.succ` is idiomatic but `x.sqrt` is not (Mathlib and this repo write `Real.sqrt x`, and `Real.sqrt` is the name used in `simp` / `rw` lemma names), so no `ℕ→Nat` / `ℝ→Real` map is added. Also skips non-bare arguments (`Fin.ropeEven (g x)`, `Fin.ropeEven 0`, `Foo.bar (f x) t`) and definition references with no argument (`simp [Fin.ropeEven]`, `#check`). The quoted reprint is located against the comment-blanked source so a mention inside a `/-- … -/` doc string does not steal the line. Warn-only. Not an AGENTS.md rule (user request) | — (AST only) |

Why `given-prop-consecutive`: the page (`render2vue` in `js/parser/lean/module.js` → `vue/lemma.vue`)
splits the `given` binders into `explicit` (before the first proposition, raw Lean), `given` (the first run of

`rw-exact` (text scan): `rw […]` (optional `at`) whose next tactic, after blank lines and comments, is `exact` of one atomic term (`h₅`, `this`, `h.symm`, or parentheses around just that — not `by` / `show` / `fun` / `calc` and not a second argument). Suggest `rwa` and dropping the `exact`. `exact` inside the rewrite brackets is not the next tactic. `<;>` is not this pattern.

`show-multiline` (text scan): a multi-line `show T by …` / `show T from …` inside `rw` / `rwa` / `erw` / `rewrite` `[…]`, or as an argument of `apply` / `refine` / `exact`. Pull it out as `have h : T := by` … then use `h` (any name, not only `this`). A one-line proof (`rw [show T by exact h]`, `exact (show T by fun_prop)`, or a line break only in the type) stays quiet. Other tactics are out of scope. `paren-by-multiline` does not see the rewrite shape: it matches a same-line `(` `by` and that parenthesis's closer.

`paren-by-multiline` (text scan) has two shapes: `(by ⏎ …)` and `(fun … => by ⏎ …)`. For the lambda, the span from the `(` to its closer is scanned for the lambda arrow (`=>` / `↦`) at bracket depth 0; when the token right after the arrow is `by` (a line break allowed, `=>⏎ by`) and the span has more than one line, the `(` is flagged. One-line bodies (`(fun i => by simp)`, `(fun i => by exact h i)`), a lambda with no `by` body (`(fun i => h i)`), and a `by` that is not the lambda body (`(fun i => ⟨by simp, by simp⟩)`) stay quiet. Several / pattern binders (`fun ⟨a, b⟩ => by`) are handled. The `(by …)` branch never sees `fun`, so the two never double-report.
